# Family Soft

Русскоязычный интернет-магазин домашнего текстиля ручной работы. Приложение использует Node.js, Express, SQLite и обычные HTML/CSS/ES-модули. Каталог и записи магазина хранятся в базе `data/family-soft.sqlite`; она и загруженные фотографии находятся вне публичной папки.

## Локальный запуск

1. Установите Node.js 22.9 или новее.
2. В корне проекта выполните `npm install`.
3. Скопируйте `.env.example` в `.env` и задайте как минимум случайные `SESSION_SECRET` (32+ байта), `ADMIN_PASSWORD`, `SBP_PHONE`, `SBP_BANK`, `SBP_RECEIVER_NAME` и `BACKUP_KEY` (32+ случайных байта).
4. Запустите `npm start`, затем откройте `http://localhost:3000`.

Таблицы и начальные данные создаются автоматически при запуске. `npm run seed` повторно применяет безопасный сид: созданные администратором записи и товары не перезаписываются. `/healthz` проверяет доступность приложения и SQLite.

По умолчанию тема оформления автоматически следует местному времени устройства: светлая с 07:00 до 16:59, вечерняя с 17:00 до 20:59 и тёмная ночью. Переключите тему в верхней строке сайта, чтобы вручную выбрать вариант; выбор сохраняется в браузере. Режим «Авто · местное время» возвращает автоматическое переключение.

В личный кабинет покупатель входит одноразовым кодом, отправленным на email из заказа. Для входа обязательны работающий SMTP (`SMTP_HOST`, `SMTP_FROM`) и `SESSION_SECRET` длиной от 32 символов. Кабинет показывает полную историю заказов и известные сайту статусы оплаты, позволяет оставить один отзыв на товар из оплаченного заказа; отзывы публикуются после проверки в разделе админки «Отзывы». Для оплаченного заказа можно создать запрос возврата и следить за его статусом. Это не инициирует денежный перевод: магазин проверяет заказ, выполняет возврат отдельно через банк или платёжный сервис, после чего отмечает запрос завершённым. Данные банковских карт не собираются и не хранятся.

## Бот MAX (локальный тест)

Бот-помощник Хелпи работает прямо в MAX, сайту и Mini App для общения, каталога, заказа и заявок на пошив не требуется. Покупатель может открыть карточку товара, пройти оформление заказа в чате, выбрать доставку или самовывоз и получить инструкции перевода через СБП. Для подачи заявки на индивидуальный пошив бот задаёт вопросы и отправляет её владельцу. Кнопка «Мои заказы» показывает статус заказов из этого чата. Владелец получает новые заявки и заказы в MAX; после проверки поступления в банке подтверждает оплату командой `/оплачен НОМЕР`, список заявок и ожидающих заказов доступен командами `/заявки` и `/заказы`. Заказы включаются только после настройки `MAX_BOT_OWNER_ID`, `SBP_PHONE`, `SBP_BANK` и `SBP_RECEIVER_NAME`; покупателю сначала показывается согласие на обработку данных. Данные карты и коды подтверждения бот не запрашивает.

1. Создайте чат-бота в [MAX для бизнеса](https://business.max.ru/self). Не публикуйте токен и не присылайте его в чат.
2. Для чат-бота отдельный веб-сайт запускать не нужно: база каталога и начальные товары создаются при первом запуске бота.
3. В терминале VS Code из папки проекта выполните `npm run bot:max:setup`; PowerShell попросит токен через скрытый ввод. Скрипт проверит токен и сохранит его в игнорируемый Git файл `.env`. На Windows команда использует системные сертификаты для подключения к API MAX.
4. Откройте диалог с ботом в MAX и нажмите «Начать». Используйте кнопки или напишите `каталог`, `товар 1`, `доставка`, `оплата`, `мои заказы`, `вопросы` или `контакты`.

Локальный режим использует Long Polling: бот работает, пока включены компьютер и процесс. Для обычного запуска используйте `npm run bot:max`; для фонового запуска Windows — `npm run bot:max:start`, для остановки — `npm run bot:max:stop`. В чате с ботом отправьте `/мой id` и внесите показанный номер в `MAX_BOT_OWNER_ID` в `.env`, затем перезапустите бота. Заполните реквизиты СБП в `SBP_PHONE`, `SBP_BANK`, `SBP_RECEIVER_NAME`. Никогда не передавайте токен и секретные ключи в чат или Git.

Боту для чата и оформления заказа не нужны `SITE_URL`, веб-сайт или Mini App. Пока не настроены MAX ID владельца или реквизиты СБП, бот не начнёт сбор персональных данных и сообщит, чего не хватает.

### Бесплатный Cloudflare Worker для постоянной работы MAX-бота

Чатовый MAX-бот можно запустить без VPS и веб-сайта на бесплатном Cloudflare Workers через HTTPS webhook; D1 хранит каталог и заказы, а каталог товаров и изображения включены в Worker Assets. Бот также ищет товары: нажмите «Найти товар» или напишите, например, `найти плед`; поиск учитывает название, описание, материал, размер и варианты. В проекте подготовлены конфигурация, D1-миграции, регистрация webhook и скрипт развёртывания. Бесплатный тариф имеет ограничения по запросам и ресурсам; проверьте текущие [условия Workers](https://developers.cloudflare.com/workers/platform/pricing/) и [лимиты](https://developers.cloudflare.com/workers/platform/limits/).

MAX рекомендует API `platform-api2.max.ru`; бот использует его в первую очередь. Если этот узел возвращает HTTP 526, бот повторяет запрос через `platform-api.max.ru`, который сейчас доступен из Worker.

1. Создайте аккаунт Cloudflare, установите/обновите зависимости (`npm install`) и войдите в аккаунт из терминала проекта командой `npx wrangler login`. Завершите вход в браузере, который открылся на том же компьютере: OAuth возвращается на локальный адрес `localhost`, поэтому удалённый браузер может не завершить авторизацию.
2. Убедитесь, что локальный `.env` содержит `MAX_BOT_TOKEN`. Если реквизиты СБП и MAX ID владельца пока не настроены, чат-бот сможет показывать каталог и отвечать, но оформление заказов останется отключено.
3. Запустите `npm run bot:max:deploy`. Скрипт создаст D1, применит схему и каталог, передаст токен и случайный секрет Cloudflare, опубликует Worker, зарегистрирует HTTPS webhook в MAX и остановит локальный Long Polling, чтобы экземпляры не конфликтовали.
4. Напишите развёрнутому боту `/мой id`. Добавьте показанный MAX ID и реквизиты в игнорируемый `.env` (`MAX_BOT_OWNER_ID`, `SBP_PHONE`, `SBP_BANK`, `SBP_RECEIVER_NAME`), затем выполните `npm run bot:max:secrets`. Секреты будут переданы в Worker, не публикуясь в Git. До этой настройки оформление заказа и заявки на пошив не включаются.
5. Проверяйте состояние по адресу `https://<worker>.workers.dev/healthz`, а логи — в Cloudflare Dashboard → Workers & Pages → `family-soft-max-bot` → Logs. В MAX используйте команды `/заказы`, `/заявки`, `/оплачен НОМЕР` и `/отменить заказ НОМЕР`.

Не отправляйте токен MAX, СБП-реквизиты и пароль Cloudflare в чат или Git. MAX требует для Webhook доступный HTTPS URL и общий секрет; его требования описаны в [официальной документации MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions). Для локальной разработки сохраняются существующие команды `npm run bot:max` и `npm run bot:max:start`.

## Публикация магазина через GitHub и Cloudflare

Исходный код хранится в GitHub, а сайт, API, MAX webhook и база D1 работают в Cloudflare Worker. GitHub Pages не запускает сервер и не используется как сервер магазина. После отправки изменений в ветку `main` GitHub Actions запускает проверки, применяет миграции D1 и публикует сайт и Worker. Адрес сайта: `https://family-soft-max-bot.a28526710.workers.dev`.

Чтобы включить автоматическое развёртывание, в настройках репозитория GitHub → **Settings → Secrets and variables → Actions** добавьте:

- `CLOUDFLARE_API_TOKEN` — API token Cloudflare с правами на развёртывание Workers и изменение D1;
- `CLOUDFLARE_ACCOUNT_ID` — Account ID из панели Cloudflare.

Не вставляйте значения секретов в исходники, GitHub Issues или чат. Workflow находится в `.github/workflows/deploy-worker.yml`; его можно запустить вручную во вкладке **Actions** или новым push в `main`. Секреты MAX webhook задаются отдельно в Cloudflare и уже не должны загружаться из `.env` или GitHub.

Каталог, товары, страницы, FAQ и блог доступны покупателям на сайте. Заказы, заявки на пошив и сообщения сайта владелец проверяет командами `/заказы`, `/заявки` и `/сообщения` в MAX; оплату подтверждает только после сверки поступления командой `/оплачен НОМЕР`. Для приёма заказов сначала задайте в Cloudflare секреты `MAX_BOT_OWNER_ID`, `SBP_PHONE`, `SBP_BANK` и `SBP_RECEIVER_NAME`. Сайт не включает прежнюю Express-админку или вход покупателей; формы заказа требуют настроенных реквизитов СБП.

## Админка и защита

Откройте `/admin`. Перед первым входом задайте `ADMIN_PASSWORD` и случайный `SESSION_SECRET` (не менее 32 случайных байт). В первоначальной настройке админка выдаст секрет TOTP один раз; сохраните его в приложении-аутентификаторе и надёжном хранилище. Для входа обязательны пароль и одноразовый TOTP-код. Сессия ограничена восемью часами; изменения требуют CSRF-токен и журналируются. Не используйте примерные или повторно используемые пароли.

В разделе настроек редактируются контактный телефон, доставка, цена упаковки, порог проверки риска и адрес самовывоза. Реквизиты оплаты нельзя менять через панель: используйте секреты среды. Загруженные товары изображения декодируются и пересохраняются в WebP через Sharp; EXIF-метаданные не сохраняются.

## Платежи

Для оформления заказа в MAX-чате заполните `SBP_PHONE`, `SBP_BANK`, `SBP_RECEIVER_NAME` и `MAX_BOT_OWNER_ID`. Для каждого ожидающего ручного перевода назначается уникальная сумма до копейки. Владелец сверяет поступление в банковском приложении и только после этого отправляет боту `/оплачен НОМЕР`; товар можно снять с резерва командами `/отмена заказа НОМЕР` покупателя или `/отменить заказ НОМЕР` владельца. Веб-магазин отдельно поддерживает `PAYMENT_MODE=manual` для перевода с сайта.

Режим `PAYMENT_MODE=yookassa` создаёт платёж СБП и принимает уведомления на `SITE_URL/api/payments/webhook`. Укажите `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в хранилище секретов и настройте HTTPS webhook в кабинете ЮKassa. Событие webhook не считается подтверждением: сервер повторно запрашивает платёж у ЮKassa, проверяет валюту и сумму, затем идемпотентно меняет статус заказа. Для фискализации в платёжный запрос можно включить `RECEIPT_MODE=yookassa`; перед запуском проверьте настройки налогового режима и НДС у бухгалтера и в тестовом магазине.

Все суммы, остатки, промокоды и доставка рассчитываются повторно на сервере по каталогу SQLite. Ключи API, банковские реквизиты и пароли не отдаются браузеру. Не принимайте переводы по реквизитам из чатов, звонков или сообщений.

## Почта и домен

SMTP включается только при наличии `SMTP_HOST` и `SMTP_FROM`; задайте также порт, пользователя и пароль. Заказ оформляется и при выключенном SMTP, но покупателю не придёт письмо — панель покажет предупреждение. `SITE_URL` задайте фактическим HTTPS-адресом deployment, затем привяжите `family-soft.ru`, включите TLS и направьте webhook ЮKassa на `/api/payments/webhook`. `trust proxy` настроен для одного доверенного прокси.

### Публикация на VPS с Docker Compose

В корне проекта есть `Dockerfile`, `docker-compose.yml` и `Caddyfile`: Caddy автоматически получает TLS-сертификаты, направляет `www.family-soft.ru` на `family-soft.ru` и перенаправляет `family-soft.online` с `www` на основной домен. Данные SQLite, пользовательские загрузки и сертификаты хранятся в постоянных Docker volumes. Перед запуском:

1. Установите на Ubuntu/Debian Docker Engine и Compose plugin; разрешите входящие TCP-порты 80/443 и UDP-порт 443 в firewall и панели VPS.
2. Скопируйте проект на VPS. Скопируйте `.env.example` в `.env`, укажите `NODE_ENV=production`, `SITE_URL=https://family-soft.ru`, случайный `SESSION_SECRET` не короче 32 символов, уникальный `ADMIN_PASSWORD`, `BACKUP_KEY` не короче 32 символов и реальные реквизиты оплаты. Для входа покупателей по email дополнительно настройте SMTP. Не передавайте `.env` в Git и ограничьте доступ к нему (`chmod 600 .env`).
3. В DNS-панели `family-soft.ru` (сейчас NS Яндекса) создайте запись A для корня (`@`) с публичным IPv4-адресом VPS и CNAME `www` на `family-soft.ru.`. В DNS-панели `family-soft.online` (сейчас NS REG.RU) создайте запись A корня (`@`) на тот же IPv4 и CNAME `www` на `family-soft.online.`. Удалите конфликтующие A/AAAA-записи этих имён. Изменения DNS могут распространяться не сразу.
4. После того как оба имени указывают на VPS, убедитесь, что `MAX_BOT_TOKEN` добавлен в `.env` на VPS (токен не передавайте в чат и не добавляйте в Git). Остановите локальный Long Polling-бот командой `npm run bot:max:stop`, чтобы он не конфликтовал с серверным экземпляром. Из каталога проекта выполните `docker compose --profile max-bot up -d --build`. Проверьте `docker compose ps`, `docker compose logs --tail=100 app max-bot caddy` и `https://family-soft.ru/healthz`.

### Постоянный запуск только MAX-бота (без сайта)

Боту нужен постоянно включённый VPS, но публичный домен, веб-сайт, Caddy и HTTPS для работы самого чата не нужны. Установите Docker на VPS, скопируйте проект и настройте `.env` с `MAX_BOT_TOKEN`, `MAX_BOT_OWNER_ID`, `SBP_PHONE`, `SBP_BANK`, `SBP_RECEIVER_NAME`. Запустите только бот: `docker compose --profile max-bot up -d --build max-bot`. Контейнер хранит каталог и заказы в постоянном Docker volume, запускается повторно после перезагрузки сервера и автоматически поднимается после сбоев. Логи: `docker compose logs -f max-bot`. Не запускайте второй Long Polling-экземпляр с тем же токеном на домашнем компьютере. Чтобы узнать `MAX_BOT_OWNER_ID`, сначала запустите бота, напишите ему `/мой id`, остановите контейнер, добавьте число в `.env` и запустите контейнер снова.

Не публикуйте приложение через проброшенный напрямую порт Node.js: внешний трафик должен проходить через Caddy по HTTPS. Сохраните резервные копии постоянных volumes отдельно от VPS и регулярно проверяйте восстановление.

## Изображения и сид

Предоставленные изображения бренда и товаров размещены в `public/img`. После установки зависимостей `npm run assets` создаёт favicon/PWA-иконки и WebP hero из мастер-фотографий; JPEG остаются резервными исходниками. Категории, примеры товаров, статьи, FAQ, страницы и выключенный промокод `WELCOME10` создаются автоматически. Цены и остатки примеров редактируются в админке.

## Текущие ограничения

Этот начальный выпуск реализует витрину, поиск/фильтрацию каталога, локальную корзину гостя, серверный расчёт заказа, ручную оплату СБП, интеграцию создания/проверки платежа ЮKassa, редактирование товаров и ключевых настроек, базовый журнал действий, статические FAQ/блог/юридические страницы и PWA shell. Опциональные SMTP-письма включаются конфигурацией.

Резервные копии SQLite шифруются AES-256-GCM ключом `BACKUP_KEY`, создаются при старте и далее раз в сутки, последние семь хранятся в `data/backups`. Если ключ короче 32 символов, копии не создаются; храните копию ключа отдельно от резервных файлов. Чтобы подготовить базу для восстановления, задайте прежний `BACKUP_KEY` и выполните `npm run restore -- family-soft-ГГГГ-ММ-ДД-время.sqlite.enc`. Скрипт расшифрует, проверит SQLite и создаст `data/restored-family-soft.sqlite`, не перезаписывая работающую базу.

В этом выпуске ещё не реализованы полная синхронизация аккаунта/корзины между устройствами, Yandex SmartCaptcha, SMS/MAX-каналы, подписки, автоматические возвраты, модерация блогов/FAQ, чат-ассистент и управление категориями/промокодами из панели. Заявки на индивидуальный пошив и сообщения с сайта доступны в админке, статус заявки покупатель может проверить по секретной ссылке после отправки формы. Админка также позволяет менять товары, ключевые настройки, заказы, отзывы и blocklist. Не публикуйте магазин для реальных покупателей до настройки интеграций, юридических текстов, политики обработки данных и проверки этих сценариев.
